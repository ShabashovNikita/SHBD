# Дизайн: нижнее меню из 4 вкладок

## Контекст

Навигация основы устроена так (`ui/navigation/`):
- `ShbdRoutes` — строковые маршруты. `bottomTabs = [HOME, PROGRESS, COACH, SETTINGS]` решает,
  на каких экранах видно меню. `GO_DESTINATIONS` — белый список для ссылок `shbd://go/<маршрут>`.
- `BottomNavBar.kt` — список `BottomTabs` (маршрут, иконка, строка) и `bottomTabs(showCoachTab)`,
  который убирает Тренера, если он скрыт (`coachTabEnabled && aiFeaturesEnabled`).
- `ShbdNavHost` — один `NavHost`. Старт: `ONBOARDING` или `HOME`. Переход на вкладку:
  `navigate(target) { popUpTo(HOME) { saveState = true }; launchSingleTop; restoreState }`,
  на HOME — `popBackStack(HOME)`. Кнопка «Назад» с любой вкладки поэтому возвращает на HOME.
- `HomeScreen` и `ProgressScreen` — полноэкранные, у каждого свой `Scaffold`, который сам
  отступает от статус-бара. `HomeScreen` сам забирает фото из `sharedImageInbox` и ярлыки из
  `shortcutEntryInbox`, только пока он показан на экране.
- В `ui/components/SegmentedTabs.kt` уже есть переключатель `ShbdSegmentedTabs`.

## Цели и не-цели

**Цели:**
- Каркас 4 вкладок, в который следующие изменения вставят свои экраны, не трогая навигацию.
- Не потерять функций: добавление еды, фото «Поделиться», ярлыки, уведомления, скрытие Тренера.

**Не-цели:**
- Новый вид Дневника (карточки по макету из ТЗ) — изменение `diary-dashboard`.
- Экран Рациона — `ration-week-screen`. Содержимое Профиля — `profile-settings-tab`.
- Переименование маршрутов-строк (`home`, `settings` и т. д.).
- Переводы новых строк на 16 языков, кроме английского и русского.

## Решения

### 1. Дневник — один маршрут `HOME` с переключателем внутри
Новый `ui/diary/DiaryScreen.kt`: сверху `ShbdSegmentedTabs` «Сегодня | Прогресс»
(с отступом от статус-бара), ниже либо `HomeScreen`, либо `ProgressScreen` с теми же колбэками,
что сейчас передаёт `ShbdNavHost`.

Почему так, а не два маршрута HOME и PROGRESS с подсветкой одной вкладки: переключение
внутри одного экрана не создаёт записей в стеке «Назад», и не нужно учить меню, что один
таб владеет двумя маршрутами. Когда `diary-dashboard` заменит Дневник, поменяется только
содержимое `DiaryScreen`.

Отступы: строка переключателя забирает отступ статус-бара (`windowInsetsPadding`), поэтому
внутренние `Scaffold` его повторно не добавляют (Compose учитывает уже использованные отступы).
Это проверяется глазами на эмуляторе: см. tasks.

### 2. Положение переключателя хранится в `ShbdNavHost`
`diarySegment` (TODAY/PROGRESS) — `rememberSaveable` в `ShbdNavHost` и передаётся в
`DiaryScreen`. Так он переживает переход на другие вкладки, поворот экрана, и его можно
выставить снаружи:
- ссылка `shbd://go/progress` → `diarySegment = PROGRESS` и переход на HOME;
- пришло фото через «Поделиться» или ярлык → `diarySegment = TODAY`, иначе `HomeScreen`
  не показан и не заберёт данные из inbox.

Альтернатива — `rememberSaveable` внутри `DiaryScreen`. Не подходит: снаружи его не выставить.

### 3. Маршрут PROGRESS остаётся только для ссылок
Константа `PROGRESS` и её место в `GO_DESTINATIONS` остаются (старые уведомления и
`shbd://go/progress`). `composable(PROGRESS)` из `NavHost` убирается, обработка ссылки
подменяет его на HOME + PROGRESS (решение 2). Новый маршрут `RATION = "ration"` добавляется
в `GO_DESTINATIONS`.

### 4. Список вкладок
`BottomTabs`:
| Маршрут | Иконка | Строка |
|---|---|---|
| HOME | `Icons.Filled.Book` (дневник) | `nav_diary` |
| COACH | `Icons.Filled.Forum` (как было) | `nav_coach` |
| RATION | `Icons.Filled.RestaurantMenu` | `nav_ration` |
| SETTINGS | `Icons.Filled.Person` | `nav_profile` |

`ShbdRoutes.bottomTabs = [HOME, COACH, RATION, SETTINGS]`. Бейдж обновления остаётся
привязан к SETTINGS. Иконки берутся из `material-icons-extended`, он уже подключён в
`app/build.gradle.kts`. Новых зависимостей нет.

### 5. Заглушка Рациона
`ui/ration/RationPlaceholderScreen.kt`: `Scaffold`, по центру иконка, заголовок
`ration_placeholder_title` («Рацион на неделю») и текст `ration_placeholder_body`. Кнопок нет.

### 6. Строки
В `values/strings.xml` (английский по умолчанию) и `values-ru/strings.xml` добавляются:
`nav_diary`, `nav_ration`, `nav_profile`, `diary_segment_today`, `diary_segment_progress`,
`ration_placeholder_title`, `ration_placeholder_body`. Старые `nav_home`, `nav_progress`
остаются: их используют другие места. `nav_settings` остаётся заголовком экрана настроек и
подписью «Назад» в подразделах.

### 7. Онбординг (доработка 26.10.2026)
- `OnboardingStep`: `WELCOME, GENDER, BIRTHDAY, HEIGHT, WEIGHT, BODY_FAT, ACTIVITY, GOAL,
  GOAL_WEIGHT, GOAL_SPEED, HEALTH_CONNECT, BUILDING_PLAN, PLAN_READY, DISCLAIMERS`. Шаги
  `DIET_MODE`, `NOTIFICATIONS`, `HOME_LOOK`, `PROVIDER` и их экраны удалены; `HEIGHT_WEIGHT`
  разделён на `HeightStep` (колесо см) и `WeightStep` (колесо кг).
- Черновик опроса хранится в DataStore как JSON (`OnboardingDraft`). Старый черновик с удалённым
  шагом не раскодируется (`objectPref` вернёт null), и опрос начнётся с приветствия — миграция не нужна.
- `StepHeader`: заголовок `headlineMedium` вместо `displaySmall`, подзаголовок `bodyMedium`, отступ
  под шапкой 20 dp. Корневой `Column` экрана получает `navigationBarsPadding()`, кнопки внизу —
  высота 52 dp и отступ 20 dp.
- Модель ИИ по умолчанию — `OnboardingViewModel.applyDefaultAi()` при открытии опроса (порядок
  выбора — в спецификации `onboarding`). Пишет активный профиль ИИ (`editActiveProfile`) и, для
  debug-ключа, `keyStore.setProfileApiKey`. Полностью встроенную модель сделает изменение
  `embedded-ai-model`.
- «Настроить главную»: экран `HomeDisplaySettingsScreen` уже был в «Приложение и экран»; в
  `SettingsScreen` добавлена строка верхнего уровня `HOME_DISPLAY` с подписью
  `settings_home_display_summary`. Недостающие русские строки (виды карточек и списка, пример дня,
  буквы БЖУ, «Увеличить/Уменьшить») добавлены в `values-ru/strings.xml`.

### 8. Единицы, колёса веса и экран плана (вторая доработка 26.10.2026)
- **Единицы.** `OnboardingState.heightMetric/weightMetric` всегда `true`; переключатель
  `UnitToggle` и `setUseMetric()` из опроса удалены, ветки футов/фунтов в
  `OnboardingHeightWheels`, `OnboardingWeightWheel` и `GoalWeightStep` убраны. Опрос не пишет
  настройки единиц; их меняют в Профиле → Личные данные → Единицы (`SettingsSheet.UNITS`).
- **Вес по умолчанию.** `DEFAULT_ONBOARDING_WEIGHT_KG = 70.4`; желаемый вес по умолчанию —
  `defaultGoalWeightKg()`: целые кг текущего веса − 5 (сброс) или + 5 (набор) и «,4». Он
  пересчитывается при смене веса и цели. 4 — середина колонки 0–9, колесо открывается ровно.
- **Прочерки на колёсах.** У `WheelPicker` новый параметр `edgePlaceholder`. Когда он задан,
  вместо пустого `contentPadding` сверху и снизу в список добавляются по 2 строки-заглушки с этим
  текстом (без семантики для TalkBack). Список не прокручивается дальше своих краёв, поэтому в центре
  всегда настоящее значение: выбрать заглушку нельзя. Индексы центра пересчитываются со сдвигом на
  число заглушек. `SplitDecimalWheelPicker` (вес в опросе, в Профиле, в диалогах) включает «—» в
  обеих колонках.
- **Экран «Твой план».** Норма = `UserProfile.tdee` (BMR × уровень активности) — калории для
  сохранения веса. План = `effectiveCalories` в пределах `planCalorieRange()`: 0…норма при
  сбросе и сохранении веса, норма…норма + 1 000 при наборе. Ползунок (шаг 10 ккал) вызывает
  `setCustomCalories()`, который заодно сбрасывает закреплённые БЖУ (`customProtein/Carbs/Fat`,
  например из ИИ-расчёта), чтобы макросы пересчитались из новых калорий по формуле. Срок —
  `planDaysToGoal()`: разница с желаемым весом × 7 700 ккал/кг ÷ дневной дефицит (или профицит),
  с округлением вверх; дата = сегодня + срок. Если план не двигает вес к цели — вместо срока
  подсказка сдвинуть ползунок. Диалог правки `PlanEditDialog` на этом экране больше не
  используется; карточки БЖУ не нажимаются. Предупреждение «проконсультируйся с врачом» — когда
  план ниже безопасного минимума `CalorieSafety.floorKcal(bmr)`.

### 9. Третья доработка 26.10.2026: прочерки, значения по умолчанию, пояснение
- `NumericWheelPicker` получил флаг `showEdgePlaceholders` (по умолчанию выключен, чтобы не менять
  колёса макросов, времени и т.п.); включён на колесе роста в опросе и в листе «Рост» Профиля.
  `DateWheelPicker` включает прочерки во всех трёх колонках всегда (дата рождения, дата записи веса).
- `OnboardingState`: `activity = SEDENTARY`, `goal = LOSE`, `goalWeightKg = 65.4`
  (`DEFAULT_ONBOARDING_GOAL_WEIGHT_KG`). Подсказка по ИМТ на шаге «Цель» только помечает вариант.
- `PlanReadyStep`: внешний `Column` + прокручиваемая часть с `weight(1f)`; текст
  `onboarding_plan_adaptive_note` — вне прокрутки, последним, прямо над кнопкой «Продолжить».

## Риски и компромиссы

- [Двойной отступ сверху или переключатель под статус-баром] → проверка на эмуляторе в
  светлой и тёмной теме; при проблеме у внутреннего `Scaffold` выставить
  `contentWindowInsets` без верхнего отступа.
- [Фото «Поделиться» при открытом «Прогрессе» не обработается] → решение 2 переключает
  на «Сегодня»; отдельная задача ручной проверки.
- [Скриншот-тесты и maestro-сценарий `progress-range-chips.yaml` ссылаются на старую
  вкладку «Прогресс»] → обновить превью; maestro-сценарий поправить на нажатие переключателя.
  Maestro-сценарии в SHBD не запускаются автоматически, поэтому это не блокирует сборку.
- [Не-русские и не-английские пользователи увидят английские подписи вкладок] → осознанно,
  переводы — позже.

- [Модель на устройстве нужно скачать (несколько ГБ) перед первым разбором фото] → приложение
  предложит загрузку при первом обращении к ИИ; без загрузки работают поиск по базе и ручной ввод.
  Встроенная по умолчанию модель — отдельное изменение `embedded-ai-model`.

- [Ползунок разрешает план ниже безопасного минимума (вплоть до 0)] → так задано в ТЗ; ниже
  минимума экран показывает предупреждение «проконсультируйся с врачом» с минимальным значением.
- [Норма = TDEE по формуле, а не по факту] → это оценка; адаптивные цели уточняют её по неделям,
  если пользователь не менял план вручную.

## План перехода
