# Дизайн: встроенная модель ИИ по умолчанию и настройка удалённой модели

## Контекст

Мотивация — в proposal.md, требования — в `specs/embedded-ai/spec.md` и `specs/onboarding/spec.md`.

Как устроено:
- Все вызовы ИИ читают один снимок настроек `PreferencesStore.aiCallConfig()` (активный профиль
  ИИ: провайдер, модель, модель для фото, адрес, ключ из `KeyStore`, запасной профиль). По
  провайдеру выбирается клиент: `GeminiClient`, `OpenAICompatibleClient`, `AnthropicClient`,
  `OllamaClient` или модель на устройстве (`OnDeviceLlmGateway` → `OnDeviceLlmClient`).
- Модель на устройстве: `services/ondevice/*`. `ModelCatalog` предлагает только E2B (2,6 ГБ);
  `ModelDownloadManager` + `ModelDownloadWorker` (WorkManager, уведомление, проверка SHA-256,
  докачка `.part`, проверка свободного места); `OnDeviceCapability.isSupported` — ABI
  arm64-v8a/x86_64 и ≥ 4 ГБ ОЗУ.
- Первая версия изменения принудительно переводила `aiCallConfig()` на `ON_DEVICE`/E2B
  (`EmbeddedAi.enforced`) и убрала из Профиля выбор провайдера.

**Найденная причина «Тренер пока недоступен с локальным провайдером».** В
`ChatService.sendMessage` для провайдера с форматом `ON_DEVICE` стояла заглушка: ещё до вызова
модели бросалась `AiError.Api(… R.string.ai_error_coach_on_device)`. Путь тренера на устройстве не
был реализован (в основе он был только в debug-эксперименте с инструментами). Поскольку первая
версия сделала `ON_DEVICE` единственным провайдером, тренер после скачивания модели всегда
отвечал этой ошибкой. Скачивание и сама модель при этом исправны — разбор еды через
`FoodAnalysisService` на устройстве работал.

## Цели / Не цели

**Цели:**
- Тренер отвечает на локальной модели.
- Пользователь выбирает: скачать локальную модель или подключить удалённую — прямо из Тренера.
- Загрузка модели по любой сети.
- Тексты ошибок ведут в существующие разделы («Профиль → …»).

**Не цели:**
- Вызов инструментов тренера на устройстве (предложить запись еды/веса) — остаётся
  экспериментом; на устройстве тренер отвечает текстом.
- Изменение промптов тренера и разбора еды.
- Встраивание файла модели в APK.

## Решения

### 1. `aiCallConfig()` снова берёт активный профиль
Принуждение `toEmbedded()` убирается из `aiCallConfigImpl`: снимок строится из сохранённого
активного профиля, как до изменения. Флаг `EmbeddedAi.enforced` остаётся только для голоса
(провайдер речи всегда `NATIVE`). Миграция первой версии (`migrateToEmbeddedAiImpl`, ключ
`embeddedAiMigrated`) не меняется: на уже установленном приложении активный профиль один раз
переводится на встроенную модель, дальше пользователь волен выбрать удалённую.
Тесты принуждения (`EmbeddedAiConfigTest`) переписываются: снимок совпадает с активным профилем,
голос всегда `NATIVE`, миграция профилей по-прежнему чистая функция.

### 2. Готовность ИИ учитывает обе модели
`AiAvailability`: `DISABLED`, `MODEL_MISSING` (ни одна модель не готова), `READY`.
Чистая функция `aiAvailability(enabled, provider, remoteConfigured, downloadState)`:
- `!enabled` → `DISABLED`;
- провайдер `ON_DEVICE`: файл скачан → `READY`, иначе `MODEL_MISSING`;
- другой провайдер: `remoteConfigured` (ключ есть, если провайдер его требует, и адрес не пуст) →
  `READY`, иначе `MODEL_MISSING`.
Значение `UNSUPPORTED_DEVICE` убирается: на таком устройстве можно подключить удалённую модель,
поэтому поддержка устройства — отдельный флаг `AppContainer.onDeviceSupported`, который влияет
только на кнопку «Установить локальную модель» и строку модели в Профиле.
Поток `AppContainer.aiAvailability` объединяет `aiFeaturesEnabled`, `activeAiProfile`, состояние
загрузки E2B и новый `KeyStore.changes` (счётчик, растёт при сохранении/удалении ключа) — чтобы
Тренер увидел введённый ключ без перезапуска.
Меню добавления еды показывает пункты ИИ, когда `availability != DISABLED`; при `MODEL_MISSING`
нажатие показывает `ModelRequiredDialog`.

### 3. Тренер на устройстве
В `ChatService.sendMessage` заглушка заменяется веткой `ON_DEVICE`:
- системный промпт — тот же `buildSystemPrompt(...)` плюс абзац «На этом устройстве инструменты
  недоступны: отвечай по данным ниже, не обещай записать еду или вес»;
- переписка — последние 6 сообщений истории, каждое обрезано до 600 символов, склеенные в текст
  «Пользователь: … / Тренер: …», затем новый вопрос;
- без фото — `OnDeviceLlmGateway.generate(system, user)`; с фото — `generateWithImage(user,
  jpeg ≤ 1024 px, system)`;
- результат — `ChatResult(reply)` без предложений записи.
`ChatService` получает `OnDeviceLlmGateway` через конструктор (необязательный параметр, `null` в
тестах облачных путей). Ошибки движка (`OnDeviceEngineInit`, `OnDeviceLowMemory`,
`OnDeviceModelNotDownloaded`) уходят в чат как обычные `AiError`.
*Почему ограничение истории:* окно контекста Gemma E2B в LiteRT-LM небольшое; системный промпт
уже содержит профиль и сводку.

### 4. Сообщение выбора модели в Тренере
`CoachModelGate.coachModelAction(lastMessage, availability, busy, handled)` меняется: карточка
(`SHOW_CARD`) показывается при `MODEL_MISSING` **всегда**, в том числе в пустом чате (первый
заход). `AUTO_ANSWER` — как раньше: модель стала `READY`, последнее сообщение от пользователя и
ещё не обработано.
`CoachModelDownloadCard` переименовывается по смыслу в карточку настройки модели (файл тот же):
- текст «Чтобы я мог отвечать, нужна модель ИИ. Выберите вариант:»;
- кнопка «Подключить удалённую модель» → `CoachRemoteSetupDialog` с инструкцией (4 шага:
  получить ключ на сайте провайдера → Профиль → ИИ-провайдер → выбрать провайдера и модель →
  вставить ключ в «Ключ API», вернуться в Тренер) и кнопками «Открыть ИИ-провайдер» (кладёт
  маршрут `settings/ai` в `AppContainer.launchDestinationInbox`, как `shbd://go/settings/ai`) и
  «Закрыть»;
- кнопка «Установить локальную модель (2,6 ГБ)» → активный профиль переводится на
  `ON_DEVICE`/E2B (`PreferencesStore.useEmbeddedModel()`), затем `startDownload(E2B, wifiOnly = false)`;
  на неподдерживаемом устройстве кнопка недоступна, под ней — «Устройство не поддерживает
  локальную модель (нужно 4 ГБ памяти и больше)»;
- во время загрузки (`Downloading`, `WaitingForNetwork`, `Verifying`) — прогресс и «Отмена»;
  `Failed` — причина и «Повторить»; кнопка удалённой модели остаётся.
Пустой чат при `MODEL_MISSING` показывает карточку вместо заставки. Поле ввода доступно:
вопрос сохраняется и получит ответ, когда модель станет готова.

### 5. Загрузка по любой сети
Отметка «Только по Wi‑Fi» убирается из карточки и из листа модели в Профиле. Все вызовы
`startDownload` передают `wifiOnly = false` → ограничение WorkManager `NetworkType.CONNECTED`.
Состояние `WaitingForNetwork` остаётся (нет никакой сети) — текст «Ждём подключения к интернету».
Настройка `onDeviceDownloadOverWifiOnly` больше не читается интерфейсом.

### 6. Профиль → ИИ-провайдер возвращается
Возвращаются файлы и ветки, удалённые первой версией: `SettingsAiSection` (профили ИИ, провайдер,
модель, ключ API, адрес, модель для фото, усилие рассуждения, лимит токенов, тайм-аут),
`SettingsFallbackSection`, `OnDeviceModelSheet`, листы в `SettingsSheets` / `SettingsPickerSheets`
и значения `SettingsSheet`. `SettingsViewModel` их методы сохранил. Изменения относительно
прежнего вида:
- в `OnDeviceModelSheet` нет переключателя «Только по Wi‑Fi», выбор только E2B;
- переключатель «Функции ИИ» остаётся первой строкой;
- выбор сервиса речи и его ключа не возвращается (голос только системный).

### 7. Тексты ошибок
Все строки, где путь начинается с «Настройки → …» / «Settings → …», переписываются на
«Профиль → …» / «Profile → …» (ru и en; прочие языки — en-текст). Строка
`ai_error_coach_on_device` удаляется вместе с заглушкой. Юнит-тест строк проверяет, что в
`values-ru/strings.xml` и `values/strings.xml` нет «Настройки →» и «Settings →».

### 8. Сообщение «нужна модель ИИ»
`ModelRequiredDialog` остаётся, тексты: «Для разбора еды нужна модель ИИ. Установите локальную
модель или подключите удалённую во вкладке «Тренер»» и аналогично для целей. Проверка — по
`aiAvailability == MODEL_MISSING` до запуска функции.

### 9. Опрос и сборка
Без изменений относительно первой версии: опрос назначает `ON_DEVICE`/E2B, `GEMINI_API_KEY` в
сборке нет.

## Решения по замечаниям 2 (29.10.2026)

### 10. Один блок «ИИ-профиль» в Профиль → ИИ-провайдер
Карточки «ИИ-профиль» и «Подключение» сливаются в одну карточку «ИИ-профиль»
(`SettingsAiSection`): «Функции ИИ» → «Профиль ИИ» (список профилей с выбором, добавлением,
переименованием) → «Провайдер» → «Модель» → «Ключ API» (для облачных) → «Адрес сервера» и
«Разрешить HTTP» (для Ollama и своего сервера) → «Модель на устройстве» (для «На устройстве») →
пояснение о приватности → «Добавить профиль», «Переименовать», «Удалить профиль». Всё, что ниже
строки «Профиль ИИ», редактирует активный профиль — так профиль меняется целиком: провайдер,
модель, ключ, адрес.
Карточка «Дополнительно» удаляется: у встроенной модели она пустая, а для облачных
провайдеров значения по умолчанию (модель для фото = основная, лимит токенов, тайм-аут) подходят.
Листы `VISION_MODEL`, `MAX_TOKENS` и др. в `SettingsSheets` остаются в коде, но не открываются.

### 11. Резервного провайдера нет
`SettingsFallbackSection` и лист `FALLBACK_PROFILE` удаляются — задать запасной профиль больше
негде. Сохранённый `FALLBACK_AI_PROFILE_ID` очищается, а `FALLBACK_ENABLED` выключается
одноразовой чисткой (решение 12), поэтому `aiCallConfig().fallbackProfile` всегда `null` и
скрытого переключения на другой профиль при ошибке нет. Сам механизм запасного профиля в
`FoodAnalysisService` остаётся в коде (на нём держатся юнит-тесты основы), но не используется.

### 12. Нет лишнего профиля «Google Gemini»
Причина: при первом запуске `ensureAiProfilesMigratedImpl` (перенос из основы) создавал
профиль по умолчанию «Google Gemini», а затем миграция на встроенную модель добавляла профиль
«Gemma 4 E2B» и делала его активным. В списке профилей оказывался чужой пользователю Gemini.
- Новая установка: профилем по умолчанию сразу становится встроенная модель (`ON_DEVICE`/E2B,
  имя «Gemma 4 E2B», `embeddedAiProfile()`); `editActiveProfileImpl` на пустом списке тоже
  создаёт встроенный профиль.
- Уже установленное приложение: одноразовая чистка `cleanUpAiProfilesImpl(keyStore)` при
  запуске (флаг `aiProfilesCleanedUp`) удаляет неактивные облачные профили без ключа, без
  выбранной модели и без адреса (созданные автоматически) и очищает `FALLBACK_AI_PROFILE_ID`.
  Профили, которые пользователь настроил (есть ключ, модель или адрес), остаются.
Чистая функция `unusedAutoProfiles(profiles, activeId, hasKey)` покрыта юнит-тестом.

### 13. Порядок в сообщении выбора модели
В `CoachModelDownloadCard` пояснение идёт перед своей кнопкой: «Работает на телефоне без
интернета…» → «Установить локальную модель (2,6 ГБ)» → «Облачный провайдер (Gemini, OpenAI…)…» →
«Подключить удалённую модель».

### 14. Тренер на устройстве видит данные дневника
Причина: `buildSystemPrompt` написан для облачных моделей с инструментами — в нём разделы «Как
пользоваться инструментами» (`get_data_summary`, `get_food_entries`…) и «Запись от имени
пользователя» (`propose_log_*`). Gemma на устройстве инструментов не получает, но видела эти
указания и отвечала пользователю «вызовите get_data_summary».
Решение: `buildSystemPrompt(..., toolsAvailable = false)` для `ON_DEVICE`:
- разделы про инструменты и `propose_log_*` и ссылки на инструменты в остальных строках не
  выводятся;
- вместо них добавляется раздел «Данные пользователя» (`onDeviceDataSnapshot(...)`, чистая
  функция): еда за сегодня и вчера (приём пищи, название, ккал и БЖУ), итоги по дням за 14 дней,
  последние 10 записей веса, сохранённые блюда (рецепты: название, ккал и БЖУ на порцию, до 15) и
  диапазон дат данных; длина раздела ограничена (≈ 3 000 символов, лишнее обрезается со старых
  записей);
- правило: «Все нужные данные уже приведены выше. Никогда не предлагай пользователю вызывать
  функции или инструменты и не упоминай их названия. Если данных за нужный период нет, так и
  скажи».
`ChatService` берёт рецепты из `PreferencesStore.recipes`. Рациона на неделю пока нет (изменение
`ration-survey` и далее); когда он появится, его сводка добавится в этот же раздел.

## Риски / компромиссы

- [Длинный системный промпт не помещается в окно Gemma E2B] → история ограничена 6 сообщениями
  по 600 символов; если движок вернёт ошибку длины, она показывается в чате как ошибка ИИ.
- [Тренер на устройстве медленный, первый ответ ждёт загрузки движка до 1–2 минут] → в чате
  индикатор «печатает»; описано в инструкции по сборке.
- [Тренер на устройстве не предлагает записать еду/вес] → известное ограничение, в журнале.
- [Загрузка 2,6 ГБ по мобильной сети] → размер написан на кнопке; пользователь решает сам.
- [Ключи удалённых провайдеров хранятся на устройстве] → в зашифрованном `KeyStore`, как в основе.

## План миграции

1. Обновление ставится поверх. Миграция первой версии (активный профиль → встроенная модель)
   выполняется один раз, если ещё не выполнялась.
2. Ранее сохранённые облачные профили и ключи не удалялись — после обновления их снова видно в
   Профиль → ИИ-провайдер.

## Решения по замечаниям 3 (29.10.2026)

### 15. ИИ всегда включён
Строка «Функции ИИ» и её пояснение удаляются из `SettingsAiSection`. Одноразовый шаг при запуске
(`seedDefaultAiProfilesImpl`, решение 16) удаляет ключ `aiFeaturesEnabled`, поэтому
`aiFeaturesEnabled` читается как `true` по умолчанию. Проверки `aiFeaturesEnabled` в сервисах
остаются в коде (на них держатся юнит-тесты), но выключить ИИ из интерфейса больше нельзя.

### 16. Два профиля по умолчанию
Одноразовый шаг `seedDefaultAiProfilesImpl(localName, remoteName)` (флаг
`aiDefaultProfilesSeeded`) запускается после чистки (решение 12):
- нет профиля `ON_DEVICE` — добавляется встроенный профиль с именем «Локальная модель»;
  профиль `ON_DEVICE` с автоматическим именем «Gemma 4 E2B» переименовывается в «Локальная модель»;
- нет облачного профиля — добавляется «Удалённая модель»: Google Gemini с моделью по умолчанию
  (`GEMINI.defaultModel`), без ключа;
- активный профиль не меняется.
Имена берутся из строк приложения при запуске (`ShbdApp`). Модель у удалённого профиля задана
явно, поэтому чистка `unusedAutoProfiles` его не удаляет. Чистая функция
`defaultAiProfiles(profiles, localName, remoteName)` покрыта юнит-тестом.

### 17. Удаление профиля в списке «Профиль ИИ»
В листе `AI_PROFILE` под «Добавить» и «Переименовать» — «Удалить профиль» с подтверждением
(как в карточке). Удаляется активный профиль; строка видна, пока профилей больше одного.

### 18. Без Ollama в списке провайдеров
Лист `AI_PROVIDER` не показывает `OLLAMA`. Уже сохранённый профиль Ollama продолжает работать и
остаётся в списке профилей.

### 19. Инструкция по удалённой модели
`coach_remote_setup_steps`, шаг 1: «Получите ключ API на сайте провайдера, например Google AI
Studio для Gemini.» (en: «Get an API key on the provider's website, for example Google AI Studio
for Gemini.»).

## Решения по замечаниям 4 (29.10.2026)

### 20. Метка профиля по умолчанию
У `AiProfile` новое поле `preset: AiProfilePreset?` (`LOCAL` / `REMOTE`; `null` — профиль
пользователя). Поле с значением по умолчанию, поэтому сохранённые профили и резервные копии
читаются без изменений; смена провайдера (`copy`) метку сохраняет. `defaultAiProfiles` ставит
метки новым профилям; на приложении, где профили по умолчанию уже созданы, одноразовый шаг в
`seedDefaultAiProfilesImpl` (флаг `aiProfilePresetsMarked`) вызывает `markAiProfilePresets`:
первый профиль «На устройстве» с именем «Локальная модель» → `LOCAL`, первый облачный с именем
«Удалённая модель» → `REMOTE`. По метке, а не по имени: переименование ограничения не снимает.

### 21. Ограничения по метке
- `LOCAL`: в карточке «ИИ-профиль» нет строки «Провайдер».
- `REMOTE`: лист `AI_PROVIDER` не показывает `ON_DEVICE`.
- Без метки: доступны все провайдеры (кроме Ollama — решение 18).

### 22. Управление профилями только в списке
Строки «Добавить профиль», «Переименовать», «Удалить профиль» и диалог удаления убраны из
карточки (`SettingsAiSection`) и остаются в листе `AI_PROFILE`. В листе они выводятся через
`SettingRow(showChevron = false)` с пустым значением — без «›» и подписи.

## Решения по замечаниям 5 (29.10.2026)

### 23. Строка профиля и черта в списке
`settings_ai_profile`: «Профиль» / «Profile»; значение строки — только `activeProfile.name`.
Лист `AI_PROFILE` озаглавлен `settings_section_ai_profile` («ИИ-профиль»); `HorizontalDivider`
перед кнопками заменён отступом 8 dp. Отрисовку на устройстве проверяет пользователь: рендер
скриншот-тестов в среде сборки недоступен.
